## 数据位置：按组件查看

| 组件 | 处理或保存的资料 |
| --- | --- |
| MCP 客户端及其模型提供方 | 工具请求、选定片段和返回的上下文，保留策略由客户端设置及条款决定 |
| 你的 Cloudflare Worker | 处理期间的明文请求和笔记，Worker secrets 中的仓库令牌及 OAuth App secret |
| Workers KV | OAuth 库管理的客户端注册、授权、令牌记录及授权流程状态 |
| 你的私有 GitHub 仓库 | 笔记、可选片段和日志、来源引用、提交元数据及历史版本 |
| 本地源码目录 | 已忽略的 `.owncontext/` 中的部署目标及指纹；setup 子进程在 `.cache/` 中的缓存和日志 |

维护者未运营资料中转服务。运行时访问 GitHub.com 完成登录及仓库操作；采用 Client ID Metadata Documents 的 OAuth 客户端还会触发 OAuth 库读取其公共元数据。客户端自身连接的模型服务也属于数据流的一部分。

OwnContext 只提供存储和工具，未接入模型调用、向量索引、定时任务、自动会话 hook 或应用分析接口。npm、GitHub CLI、Wrangler 和托管平台有各自的网络行为及遥测设置。setup 子进程和项目 build 命令会关闭 Wrangler metrics。

## 明文处理：私有仓库的边界

私有仓库限制 GitHub 访问，HTTPS 保护传输。Cloudflare 和 GitHub 仍会处理明文，客户端获得可读内容；当前实现没有应用层端到端加密。请把密码、私钥、会话 cookie 等凭据留在专用密钥系统中。

Worker 使用单独的细粒度仓库令牌。GitHub OAuth 登录的 scope 为空，同时检查 login 和数字 ID；OwnContext 再签发自己的客户端令牌。客户端连接时只需 OwnContext 令牌。详见[权限说明](permissions-and-scopes.md)。

## 来源与修正：客户端负责判断

`remember` 保存客户端提供的 `stated` 或 `inferred` 标签。来源引用及发生日期为可选字段，缺少引用时会标记为客户端转述。服务只保存引用文本，其内容及真实性需客户端或用户核对。

客户端负责保留来源、区分事件时间与笔记 `updated` 日期，并按需保存被替代的旧陈述。`update_note` 在校验 SHA 后替换正文，修正内容及来源保留策略由客户端编写。授予写权限时，需要考虑整篇笔记被修改的范围。

`remember` 按笔记路径、事实文本、来源标签去重。同一事实改带其他来源或日期，重复调用仍会跳过；修正这些字段请用 `update_note`。保留更正历史中的原始事实标记，可以避免旧请求重试时再次添加被替代的事实。

## 片段采集：先选取再保存

可选工具 `capture_conversation` 只接受 `user` 和 `assistant` 行，以 JSONL 原样保存，标记为部分覆盖，**没有自动脱敏**。工具说明要求客户端只提交用户选定的可见文本；选取过程和可见性依赖客户端遵守约定，服务自身无法独立验证。

重试时保留相同的 `source`、`conversation_id`、`batch_id`、`captured_at` 和消息内容。同一目标月份内，用同一批次标识提交不同内容会被拒绝；改变月份可能产生另一个文件。这是批次级幂等，其他批次中的重复内容仍可能单独保存。

## 日志与保留：旧版本仍有副本

应用工具日志仅含工具名和状态码，提供的 Worker 配置默认关闭 observability。依赖库、托管平台、访问日志及命令行工具可能记录其他请求或账号元数据，分享前需检查。发布扫描默认排除已忽略的本地部署状态和缓存；一旦这些文件加入 Git，就会纳入扫描。

发布扫描器默认运行通用规则。项目专属标识通过私有本地环境或 CI secret 中的 `OWNCONTEXT_PRIVATE_MARKERS` 传入，值为非空字符串组成的 JSON 数组。命中的文件名会被隐藏，配置格式错误会让检查失败。标识列表及其摘要都应留在私有环境中。

Git 历史、克隆、备份、客户端会话和平台保留机制可能继续保存旧内容。修正或删除当前文件只改变当前版本。移除客户端连接配置也不一定撤销服务端授权，具体操作见[恢复与卸载](recovery-and-uninstall.md)。
